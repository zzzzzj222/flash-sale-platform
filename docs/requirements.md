# 业务需求与首版验收边界

本文描述当前实现的目标与职责。接口细节以 [接入契约](integration.md)、[OpenAPI](openapi.yaml) 和当前源码为准；未实现能力见 [扩展需求](extensions.md)。

## 适用场景

商品秒杀、非选座票务和预约名额：业务系统把独占配额交给本服务，用户提交申请，排队后获得限时预占，支付核验成功后确认成交，取消或超时归还配额。当前每个请求只操作一个活动的一种资源，资源以数量计量，不处理价格、指定座位或组合商品。

## 职责划分

| 主体 | 必须负责的事项 |
| --- | --- |
| 秒杀服务 | 活动配额、时间窗口、接入方隔离、限流、请求幂等、异步处理、库存与限购、确认/释放、状态查询和结果通知 |
| 可信业务后端 | 用户登录及资格、统一用户映射、请求归属校验、配额划拨、订单与金额、支付验签、退款补偿、发货或出票 |
| 网页/小程序 | 展示活动与状态，调用业务后端，按退避策略查询，展示付款期限与失败原因 |
| 部署运维 | 配置接入方凭证、HTTPS、数据库及消息队列、安全访问、监控告警、备份与恢复演练 |

同一业务跨渠道使用相同接入方身份与统一用户编号，才能共享库存和限购；不同接入方独立隔离。相同 `resourceId` 不会自动合并不同活动的库存，外部库存不得重复划拨。

## 已实现需求与验收要求

| 编号 | 需求 | 验收要求 |
| --- | --- | --- |
| R01 | 创建活动 | 校验资源、标题、配额、限购、预占时长和活动起止时间；创建后规则不可编辑 |
| R02 | 异步受理 | Redis 原子保存预扣结果与待投递申请，返回 202，MySQL 异步落库；202 只代表受理，响应也可为 REJECTED |
| R03 | 请求幂等 | 同一接入方的相同请求编号与参数返回原记录；变更活动、用户或数量返回 409 |
| R04 | 库存一致性 | 并发处理后配额不为负；重复消息不会二次扣减；取消与过期最多归还一次 |
| R05 | 用户限购 | 同一活动的有效预占与已成交合计不超过限额；取消和过期释放占用 |
| R06 | 成交确认 | 只有有效预占可以确认；同一订单可重复确认，换订单冲突；付款晚到由业务系统补偿 |
| R07 | 取消与到期 | 排队请求可取消或超时拒绝；预占可取消或到期释放；已成交不能通过释放接口退库存 |
| R08 | 认证与隔离 | API 使用后端接入凭证；跨接入方访问不可见；活动及失败通知管理需要 admin，指标需要 operator |
| R09 | 故障恢复 | RabbitMQ 不可用时已受理请求可在恢复后重投或到期；Redis 不可用时拒绝新的受理并返回 503 |
| R10 | 结果通知 | 配置后签名投递，接收方按事件编号去重并处理乱序；失败退避重试，达到上限可人工重投 |
| R11 | 本地演示 | 开关默认关闭，启用后可在本机模拟用户和付款，复用核心库存流程 |

实现位置：`backend/src/main/java/com/flashsale/api` 定义接入接口，`core` 负责事务与规则，`messaging` 负责消息与通知，`demo` 和 `web` 提供演示。数据库约束位于 `backend/src/main/resources/db/migration`。

## 状态与数据要求

- `QUEUED`：已受理，尚未获得库存；可进入 `RESERVED`、`REJECTED` 或 `RELEASED`。
- `RESERVED`：已获得限时库存；可进入 `CONFIRMED`、`RELEASED` 或 `EXPIRED`。
- `CONFIRMED`、`RELEASED`、`EXPIRED`、`REJECTED`：当前流程的终态；重试查询不会重新发起抢购。
- 用户编号和资源编号保持大小写区别，业务侧需建立统一映射。所有业务时间使用 ISO 8601，入口排队期限由 Redis 时间计算，最终预占、确认和过期由数据库时间裁定。
- 活动、预占、限购与事件由本服务持久化管理；业务侧通过 API 或通知交互，不直接修改这些表。

## 验证与上线前提

自动化验收入口为 `scripts/verify.ps1`，端到端场景在 `SaleFlowIT`，签名测试在 `WebhookSignatureTest`；历史执行结果见 [验证记录](verification.md)。本地演示和一次基础负载测试不能证明生产容量。

正式业务上线前需要在目标环境确定并测量受理吞吐、受理 P95、排队至预占耗时、超时率、锁等待、消息积压和通知失败率，并约定告警阈值与故障处理流程。还需验证真实身份与支付、退款补偿、凭证轮换、数据留存及备份恢复。当前未承诺几万并发、高可用或灾备指标。
